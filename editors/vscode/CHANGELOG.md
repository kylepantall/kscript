# Changelog

## Unreleased

- Words joined by `-`, `+`, `/` or `.`, such as `my-post`, `api.corp.com` and `1.4.2`, are recognised by a type's `pattern` like single words, and so are patterns on types built on `domain`, `semver` and other native types written as words.
- **Check This File** saves and checks a single script and reports its diagnostics in Problems, including when no project is open.

- Project commands use the active workspace folder and stop if its files cannot be saved. Standalone scripts and tests run from their own directory. Workspace symbol search follows folders added or removed during the session.
- Open the install guide from an empty window, or select a custom CLI by its name on `PATH`. Both script forms have valid editor word patterns, and selecting a name before `->` in code leaves the arrow intact.

- Two new native types. A `slash_path` is names joined by `/` (`/docs/start`, `/My Apps/Notes`), written without quotes and coloured as a value; `$name` and `{ expression }` in one are filled in, and `{id}` stays a route parameter. Route paths need no quotes either: `Get(path: /people/{id})`. A `date_format` (`dd-MM-yyyy`) is checked as you type, so `YYYY` or `DD` is underlined with what to write, and typing one after `date_format =`, `->format(` or `->to_date(` suggests the letters with what each shows.
- Values such as `1.4.2-beta.1`, `10.0.0.1` and `dd-MM-yyyy` given without quotes to a parameter whose type reads text are checked against that type instead of being reported as unknown names.
- Suggestions in views: in `views/auth/account.html`, `$` offers the variables the controller passes with `@view('auth/account', data: { ... })`, `$data.` offers their fields, and a loop such as `<for each="t" in="$data.tokens">` knows the fields of `$t`. Hovering a view's variable says which controller gives it, and Go to Definition opens the call. A page with `<import package="KScript.Auth" />` gets `$session`, and `$session->` lists its methods. `@user()` and `@api_tokens()` results offer their fields everywhere.
- One way to write each thing, and the editor says so. A spelling that was renamed or removed is underlined with what to write now: `to:` is `into:` for the variable a result goes into, argument names use `_` (`max_tokens`, `on_click`), text arguments take quotes (`title: "Results"`), booleans are `true` and `false`, a function is named `@name`, a type is named bare and called to make a value (`Repo($data)`), counting is `->count()`, and the error types are `Query` and `Connection`. Most have a quick fix, and **KScript: Check Project** with `kscript check --fix` rewrites a whole folder. The docs have the full list under **What changed**.
- A `{ }` in double quotes always holds an expression, whatever it opens with (`"{ User->count() } users"`, `"{ 1 + 2 }"`), in a value as in a statement's text. Text with braces of its own goes in single quotes or doubles them (`'/users/{id}'`, `"/users/{{id}}"`).
- A name of your own that breaks the naming rules is underlined (KS6013): functions, variables, fields and arguments are `snake_case`, and types, models, enums and error types are `PascalCase`. The built-in names are held to the same rules by the engine itself, so suggestions never offer a name spelled another way.
- Error messages in a `.kscript` file are worded for `.kscript`: they say statement and argument and show `name: value`, not XML tags and attributes.
- Highlighting matches the language: `is`, `++`, `--` and `%=` are no longer coloured as operators, and the comparison words (`lt`, `ge`, `eq`) are coloured only in XML, where they are written.
- Scripts are `.kscript` files, or `.ks.xml` for the XML form. `.ks` and plain `.xml` files are no longer treated as scripts.
- `kscript.json` keys are `snake_case` (`print_width`, `warnings_as_errors`, `make.syntax`); an old key is an error that names the new one.
- The samples the docs point to are `.kscript` files, and every example in the guides is checked by the linter, so what you copy has no warnings.
- One spelling for each piece of syntax in `.kscript` files. A `match` statement writes its arms like a match expression, `1, 2 => echo "low"`, `_ when $n > 9 => { }` and `_ => { }`, and typing inside a match offers those three; `case`, `when` and `default` blocks are reported with a quick fix that writes the arm. The second spellings are errors with a quick fix, and the script doesn't run until they are rewritten (`kscript check --fix` does it for a whole project): `$x = 3` and `fn($n)` (names are declared bare), `lt`/`gt`/`eq` and the other comparison words (symbols in `.kscript`; XML keeps the words), `else if`, `key = value` in arguments and `catch A, B`. Highlighting follows: `_` is a keyword in a match, and the comparison words are no longer coloured as operators in `.kscript`.
- Plain facts about a value are fields: after a dot, `$response.` offers `status`, `is_ok` and `text`, `$file.` offers `name` and `size`, and `$date.` offers `year` and `weekday`, each with its type on hover. Calling one (`$file->size()`) or using a renamed method (`$cache->put()`, now `->set()`) is marked with a quick fix that rewrites it.
- A length of time is highlighted as one value (`30s`, `500ms`, `1h30m`), and a time written without its unit or in quotes (`timeout: 30`, `ttl: '10m'`) gets a **Write 30s** quick fix (KS6018).
- Help writing types and jobs, like C#'s "implement missing members" and "generate overrides": a job without `fn handle()` gets an **Add fn handle()** quick fix, and the lightbulb on a job offers **Add fn failed(err)**. On a joined type (`type Admin with [User]`) it offers **Override fn greet(who: string) from User** for each method a base gives it. A method two bases both give is an error with a **Declare fn label in C** fix, as at run time. Each fix writes a stub in the file's own format.
- A **Get Started with KScript** walkthrough on the Welcome page: install, write a first script, run it, fix a mistake, find out what you can write, and start a project.
- **KScript: New Script** (also in **File > New File…**) opens a short script that runs as it is, with a variable, a function, a list and a loop to change.
- Suggestions put what a script uses every day first. An empty line offers `echo`, `if`, `for`, `fn` and `while` before the rest (in a test file, `test`, `expect` and `describe` come first), text offers `->count()`, `->upper()`, `->lower()` and `->trim()` first, lists `->count()`, `->map()` and `->filter()`, and your own variables come before the built-in ones, the nearest first.
- A call with several plain values shows what each one is: `$name->pad_left(10, '.')` reads as `pad_left(width: 10, char: '.')`. Arguments that already have a name, variables and one-argument calls are left alone.
- Hovering a command or method shows an example written the way the file is written (`.kscript` or XML), and ends with **Open docs**, which opens the docs on that name.
- A function shows how many times it is used (**3 uses**) above its first line, or **used in other files** when only another file calls it. Click it to list the uses.
- **Go to Symbol in Workspace** (`Ctrl+T`) finds the functions and constants of every script in the folder.
- `'-' * 20` is known to be text, so its methods are offered.
- Run a script from the editor: the run button in the title bar, `F5`, **KScript: Run Script**, or the **▶ Run** line above the first statement. The script is saved and runs in the terminal, and if it stops with an error, the line it stopped on is underlined and listed in Problems.
- Tests are in the Testing view: every `*.test.kscript` and `*.test.ks.xml` file with its groups and tests, each runnable on its own, with failures shown at the check that failed. A **▶ Run test** line sits above each test, and **▶ Run all tests in this file** at the top.
- New commands: **Serve Site**, **Check Project** (results go to Problems), **Format Project**, **New Project…** and **Open Docs**.
- A new file set to KScript before it is saved (`.kscript` syntax) now gets errors, completion and hovers, and can be run.
- `kscript.codeLens.enabled` turns the Run lines off.
- Mistakes that used to wait until the script ran are now warned about as you type. A misspelt field of a map (`$person.nmae` for `{ name: ... }`) asks "Did you mean name?" with a quick fix. `$name.upper` is pointed at `->upper()`. Arithmetic that can only fail (`'Joan' - 1`, `[1, 2] + 3`) and text given where a number is needed (`->repeat('x')`, or `@double('five')` for `fn double(n: int)`) are underlined. Only certain mistakes are reported: `'5' - 1`, `'ab' * 3` and joining text with `+` are all left alone.
- Signature help and hovers show which arguments of the built-in methods are numbers, such as `->repeat(count: number)`.
- Errors a learner can act on. A word from another language is answered with what KScript writes, and a quick fix makes the change: `print`, `println`, `console.log` and `puts` become `echo`; `function`, `def` and `func` become `fn`; `var` is dropped; `x++` becomes `x += 1`; `foreach`, `switch` and `raise` name `for`, `match` and `throw`; `@len($list)` points to `$list->length()`. In a `.kscript` file, messages no longer talk about `<elements>` or XML.
- A line left unfinished (`total = 5 +`) is reported on that line, not on the correct line after it, and a missing quote ends with its line, so the rest of the file is still checked.
- `"Double quotes"` now fill in `$name` and `{ }` everywhere, not only after `echo`, and the names inside them get hovers, completion, rename and error checks. `'Single quotes'` keep text as written: a warning with a quick fix to double quotes appears when they hold a variable, as in `greeting = 'Hello $name'`.
- A variable given a number and later given text is no longer warned about string methods.
- Every error code is a link: click `KS4001` in a problem to open what it means and how to fix it.
- Only what works is suggested, in every place: a date, number, bool or file is no longer offered string methods such as `->json()` or `->upper()`, which fail at run time (use `->to_string()` first, or `->to_json()`). A method a package or an `extend` block adds is offered.
- Signature help in `.kscript` statements: inside `log(‸)`, `wait(‸)` and other element statements, the tooltip lists the arguments (`log(level?: trace|debug|…, message?: text, category?: text, fields?: any)`) and highlights the one you're writing, or the next one not written yet. Parameters are now sent as their exact place in the signature, so the right one is highlighted even when its name also appears earlier in the label.
- KScript files get their own "K" file icon in the explorer and on editor tabs: `.kscript`, `.ks.xml` and their test files. It shows with VS Code's default file icon theme, and with any icon theme that has no icon of its own for KScript.
- Named arguments show as soon as you type `(` or `,` in a call (commands, methods and your own functions), with the enum values and true/false flags the next argument takes. Picking an enum parameter's `name:` lists its values straight away. Brackets and commas elsewhere, such as `(1 + 2)` or `[1, 2]`, don't open the list.
- ``` blocks only name languages KScript knows (`text`, `sql`, `html`, `css`, `js`, `json`, `md`, `latex`, `yaml`, `xml` and their long names). A typo such as ```` ```textc ```` is an error that suggests `text`, and the editor suggests the languages after the fence.
- Doc comment tags: in `///` comments (and `<!--- -->` in XML), typing `@` suggests the tags (`@param`, `@arg`, `@returns`, `@example`, `@deprecated`, `@see`, `@public`, `@llm`, `@prefer`, `@avoid`, `@pitfall`, `@agent`), with an `@param name` for each parameter not described yet. A name after `@param` or `@arg` is completed from the function's parameters, and hovering a tag explains it. Tags written once (such as `@returns`) aren't offered again, and other suggestions stay out of doc comments. `@arg` and `@argument` mean `@param`. All tags are highlighted, in XML doc comments too.
- Suggestions everywhere: completion now answers in every place you can write something, in `.kscript` and XML files alike. That covers blank lines and statement starts, inside a statement (`y = @round(‸)`), right after `=`, `echo`, `return`, `if`, `in`, an operator or `|>`, match cases, `} else`, parameter types (`fn f(a: ‸)`), `import ‸` (packages), `import a, ‸ from "lib.kscript"` (the file's functions, constants, types and enums), `KScript.‸` (`KScript.Routes`, `KScript.Window`), route handler bodies (`$request`, `$json`, `$query`, path `{parameters}`) and the empty text of `<echo>` (Ctrl+Space).
- Only what works is suggested: no planned features, no XML-style `name="..."` arguments in `.kscript` files (they get `name: value`), only cases inside `match`, and no `$lib.` for an import alias. Commands, statements, elements and methods from a package are only suggested once the script imports it (built-ins always are), at the top level, inside functions and after `->`. Using one anyway is an error with an **Add import** quick fix.
- Docs in your format: in a `.kscript` file, hover and completion docs name elements the `.kscript` way and show examples converted to `.kscript`. Element names in descriptions are no longer swallowed as HTML ("in its file or `describe`").
- Statement snippets in both formats: `if`, `elif`, `else`, `for`, `while`, `fn`, `try`, `catch`, `match`, `case`, `type`, `enum`, `describe`, `test`, `Get`/`Post` routes and more.
- VS Code's own word and snippet suggestions are off in KScript files, so only KScript's suggestions show (no unrelated snippets from other extensions). Typing `>` at the end of a start tag in a `.ks.xml` file adds the end tag (`kscript.autoCloseTags`).
- Completion while typing: a word at the start of a statement now offers keywords (`echo`, `if`, `for`, `fn`, `return`, ...), `@commands`, your functions and variables, with no trigger character needed. In XML scripts a bare word on its own line offers elements and adds the `<`. In expressions, typing `e` now matches `@env` and `$email` (they filter on the bare name).
- Enter on an empty `///` line in a `.kscript` file ends the doc comment instead of starting another `///` line.
- Shorthand conditions: `<if $user.is_logged_in>`, `<elif …>`, `<while …>`, `<match …>` and `<assert … />` are highlighted, checked and completed like `test="…"`, in scripts and pages. The `<if>`, `<elif>`, `<while>` and `<match>` snippets use the short form.
- The language server restarts by itself when the `kscript` binary changes (after `kscript update`, a reinstall, or a rebuild of a source `KScript.dll`), so the editor stops showing errors from the old version. A notice names the new version.
- When the `kscript` it finds is an older release than the extension, the extension says so and offers to run `kscript update`.
- Standards: `kscript.json` and standard files (`kscript-standard.json`, `*.kscript-standard.json`) are validated and completed, including `"standard"`, `"extends"` and the built-in `kscript:recommended` and `kscript:strict`. Editing a standard file re-checks open files straight away.
- `.kscript` files (the brace-style format) get their own language, "KScript (code)", with a grammar for keywords, `x = ...` assignments, `"text { interpolation }"`, `'strings'`, `$variables`, `@commands`, `name(attr: value)` elements and `///` doc comments with `@param`/`@returns` tags. Errors, hover and completion come from the language server as before, and Format Document tidies them too: indentation, one statement per line, `} else {`, and spacing after commas and colons and around `=`. Two new rules, `spacing` and `braceStyle`, turn the last two off, and `// kscript-fmt: off` / `// kscript-fmt-ignore` leave parts of a file alone.
- Formatting: **Format Document** and format on save tidy scripts and `kscript serve` pages with the same formatter as `kscript fmt`: indentation by nesting, one statement per line, tidy start tags, no trailing spaces. Text, attribute values, comments, CDATA and `<pre>`/`<textarea>`/`<script>`/`<style>` content are kept. The style comes from the `format` section of `kscript.json`, which the extension now validates and completes, or else from your editor's tab settings. Each rule can be turned off in `format.rules`, and `<!-- kscript-fmt: off -->` / `<!-- kscript-fmt: on -->` or `<!-- kscript-fmt-ignore -->` leave parts of a file alone.
- Types everywhere: functions know what they return (from `value="..."` or their `<return>`s, including imported ones), so `<let name="p" value="@person()" />` offers `$p.name`. Parameters take the type of their default (`count = 0`), `match` expressions the type of their arms, and a variable declared as `null` takes the type of the first value `<set>` gives it.
- Inlay hints show types you haven't written: `<let name="people": list<{ name: string, age: number }>`, `<for each="p": { name, age }>` and `params="x: int" → number`. Turn them off with `editor.inlayHints.enabled`.
- Hovers show structural types (`{ name: string, address: { city: string } }`, `list<number>`), and method completions show what each method returns, with the value's own methods first.
- `$name->` and `$name.` complete in plain element text too (`<echo>Hi $person.‸</echo>`), not only inside `{ }`.
- Notebook-style blocks: a thin line separates the top-level blocks of a script (each comment-headed section, or each function, loop and `if` when there are no comments). Set `kscript.blocks.dividers` to turn it off, or change the `kscript.blockDivider` colour. Elements and comments fold.
- Highlighting: control-flow tags (`<if>`, `<for>`, `<return>`...) are coloured as keywords and declarations (`<let>`, `<fn>`, `<import>`) as storage types; type names in `params` and `type="..."` are coloured as types; the text of `<echo format="json">` is highlighted as JSON.
- Completion pops up as you type inside attribute values (VS Code turns quick suggestions off in strings by default).

- Tests: **KScript: Run Tests** runs `kscript test` for the workspace, and test files (`*.test.ks.xml`) get a Run Tests button in the editor title bar. Test files know the KScript.Test elements (`<test>`, `<describe>`, `<expect>`, `<assert>`, `<expect-error>`, `<capture>`) without an import, and `kscript.json` completes the new `test` settings.
- Completion knows more about your data: `@read_json('data/people.json')` reads the file, so `$person.` offers `name`, `age` and so on, and nested objects and lists work too.
- Lambda parameters take the type of the list's items: in `$people->filter(fn(p) => $p.age gt 18)`, `$p.` completes its fields. This also works for `|>` pipes, `reduce` and `sort`, and `->map(fn(p) => $p.name)` is known to be a list of text.
- Components: `<person-card ` offers the component's props, which are the variables its file uses without declaring. Completing a component name fills in every prop.
- `.html` pages get KScript `{ }` highlighting again. VS Code opens `.html` files with its `text.html.derivative` grammar, which the page grammar wasn't injected into, so only plain HTML colours showed.
- `<slot />`, `<hero />` and other self-closing elements in pages are no longer marked as errors by the HTML grammar.
- `kscript.json` is validated against a bundled schema, with completion and hover for its settings, and may contain comments.
- The language server applies the project's `kscript.json` lint rules and excluded paths.

## 0.1.0

- First release: diagnostics, completion, hover, signature help, go to definition, references, rename, outline, semantic highlighting and quick fixes for KScript scripts and `kscript serve` pages, using the installed `kscript lsp`.
